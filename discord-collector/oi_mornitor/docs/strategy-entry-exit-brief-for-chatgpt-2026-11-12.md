# 策略入场/出场说明（供 ChatGPT 优化 / 组合）

- **用途**：把现有系统规则讲清楚，便于提出更优单策略或组合过滤；不是下单授权。
- **代码时点**：2026-11-12（`Desktop/script` · `oi_mornitor`）
- **回测窗口**：约 2026-05-14 → 2026-11-12；周期 1h+4h；Binance 现货 K 线
- **资金口径**：保证金每笔 **1 USDT**；盈亏(u)=ROE%/100；杠杆 BTC/ETH **100x**，山寨 **20x**
- **关键结论（已测）**：结构层胜率约 47–52%，但盈亏比约 0.55–0.69（亏大赢小）→ 合计亏损；昨晚三类研究策略是**二次标签**，盈亏几乎复读结构层。

## 0. 通用执行层（结构/K线结算共用）

### 入场
| 项 | 规则 |
|---|---|
| 触发 | 信号确认柱收盘后 |
| 入场价 | **下一根开盘价**（`next_bar_open`） |
| 滑点 | 单边 **0.03%**（买入加、卖出减） |
| 手续费 | 单边 **0.06%**（双边计入净变动） |

### 止损 SL（`build_settle_plan`）
对多单：SL = `max(更紧候选)`，且距离至少满足地板。  
对空单：SL = `min(更紧候选)`，且距离至少满足地板。

候选来源：
1. 结构 **invalid / defense**（信号自带防守位）
2. **ATR×k**（按市值梯队）
3. 价格 **cap%** 上限
4. 距离地板：主流（BTC/ETH/SOL）约 **0.4%**，其余山寨约 **0.8%**；再与结构距、ATR 距取 `max`

风险单位 `R = |entry − SL|`。

### 止盈 / 分批（结构类预设）
当 `type_label` 含：二次探底 / Spring / 流动性掠夺 / 顶部结构 / 头肩 / M顶 / 圆弧 → **structure 预设**：

| 档 | 权重 | 目标 |
|---|---:|---|
| TP1 | 30% | **1.5R** |
| TP2 | 30% | **3.0R** |
| Runner | 40% | 触及 TP2 后激活跟踪；结构类 `runner_trail_pct≈7%` |

**其它预设**（本轮主回测较少用到）：
- 量价确认/推进：TP1=1R / TP2=2R，权重 0.4/0.3/0.3
- 高潮反转等：TP1=1R / TP2=2R，权重 0.5/0.3/0.2
- 默认（含射击之星等）：TP1=1R / TP2=2R，权重 0.3/0.3/0.4

### 行走规则（5m 精细结算）
1. 同根优先：**先判 SL**，再判 TP（悲观）
2. 打到 TP1 → 平 30%；**余仓止损推到保本（entry）**
3. 打到 TP2 → 平再 30%；Runner 激活
4. Runner：沿极值按 `runner_trail_pct` 跟踪，直到止损或核实窗结束
5. 核实窗：按周期×市值梯队（1h 约 6h 量级；4h 更长）

### 杠杆与 ROE
`pnlPct(ROE) = 价格净变动% × 杠杆`（已扣费+滑点）。

## 1. 结构形态（可结构回测）

> 检测在 1h/4h K 线上；方向见下表。`invalid/defense` 写入结算 SL 候选。

### 1.1 `bottom_secondary_test` · 底部二次探底确认 · **多**
**入场（确认）**
1. 先出现「恐慌高潮」：相对 20 均量放量（约 ≥2×）+（长下影或大阴实体）
2. 之后若干根内二次探底：L2 落在 L1 附近容差带内
3. 确认柱：收阳且收盘在 K 线偏上位置，**或**看涨吞没
4. 触发柱 = 二次确认柱；`defense = min(L1,L2)`

**出场**：通用结构结算（1.5R/3R 分批 + TP1 后保本）。

**6m 表现摘要（1u）**：笔数最多的拖累项（BTC 145 笔合计约 -37.6u）。

---

### 1.2 `shooting_star` · 射击之星 · **空**
**入场（几何）**
- 上影 ≥ 实体×wick_ratio，且 ≤ 实体×max_ratio
- 下影显著短于上影
- （回踩引擎路径还会要求靠近布林上轨等背景）

**出场**：默认预设（1R/2R），非 structure 的 1.5R/3R。

---

### 1.3 `consecutive_flat_shooting_star` · 连续走平射击之星 · **空**
- 连续走平 + 射击之星组合（主流白名单路径）
- 本 6m 窗口四币检出多为 **0**

---

### 1.4 `hs_vegas_break` · 顶部头肩顶 · **空**
**入场**
1. 三个摆动高：左肩≈右肩，中间更高为头
2. 颈线取左右肩之间低点区域
3. 触发：收盘跌破 Vegas 中轨（由上穿下），或破颈线且收在中轨下
4. 需放量与顶部突破质量过滤
5. `defense = 右肩高`

**出场**：structure 预设 1.5R/3R。

---

### 1.5 `m_top_vegas_break` · 顶部 M 顶 · **空**
**入场**
1. 两摆动高近似等高；中间有下探
2. 之后实体收盘跌破 Vegas 中轨（交叉）
3. 放量 + 质量过滤
4. `defense = max(两高)`

**出场**：structure 1.5R/3R。  
**备注**：样本少时偶见正期望（如 BTC 7 笔、UNI 11 笔），不稳定。

---

### 1.6 `liquidity_sweep` · 顶部流动性掠夺 · **空**
**入场**
1. 浅刺破前摆动高（有限幅度）
2. 长上影、收在前高之下、收盘偏 K 线下部
3. 放量
4. `defense = 当根高点`

**出场**：structure 1.5R/3R。  
**备注**：相对结构子集里较不差（BTC/DOGE 小幅正）。

---

### 1.7 （相关未主跑）`spring_2b` / `curvature_decay`
- Spring：跌破前低后 1–3 根放量收回 · 多
- 圆弧顶：动量斜率转弱 · 空  
本轮离线 kinds 主清单未作为重点结算。

## 3. 回踩引擎（`run_backtest` / `long_pullback` + `short_shooting_star`）

### 入场状态机
**A. 做多回踩 `long_pullback`**
1. 阶段：带量真突破 → `BREAKOUT` / `WAIT_PULLBACK`
2. 回踩锚点优先级：`supply_wall` → 布林中轨 → Vegas 中轨
3. 价格触及锚点 **且** 缩量
4. （可选）OI 变化不过度流出
5. 扳机触发做多

**B. 做空 `short_shooting_star`**
1. 反转背景：曾跌破布林中轨 → 收回中轨上 + 更高低点 → `REVERSAL_WATCH`
2. 靠近布林上轨 + 射击之星几何 → 扳机做空

### 出场（成本防守 + 推动止损；价格%口径后再×杠杆）
| 参数 | 默认 |
|---|---:|
| 初始止损 | **2.0%** |
| 浮盈达 | **1.0%** → 止损推到保本 |
| 浮盈达 | **2.5%** → 启动跟踪 |
| 跟踪幅度 | **1.2%** |
| 费/滑点（引擎内） | 0.04% / 0.02% |
| 最长持仓 | 48 根（回测用 1h） |

**6m 表现**：胜率 15–29%，盈亏比虽 >1，但胜率过低 → 合计仍亏。

## 4. 昨晚三类研究策略（只读匹配 · 无独立出入场）

> **关键限制**：`readOnly=True`，`scheduler=none`，`backtestStatus=planned_p1`。  
> 它们**不产生自己的 entry/SL/TP**；只在已有 alert + PA 上下文上打标。  
> 本轮 6m 回测 = 在**已结算结构信号**上二次匹配 → 盈亏沿用结构结算。  
> 因此「优化昨晚策略」必须先补：**独立触发条件 + 独立 SL/TP**，否则只能优化「过滤哪些结构单」。

### 4.1 `liquidity_reversal` · 流动性反转
**匹配步骤（可重叠）**
- 存在流动性区
- sweep（区 mitigated 或 tag 含 swept）
- reclaim（区 reclaimed 或 `liq_sweep_reclaim`）
- 结构确认：CHoCH / BOS 事件 tag
- 入场区：靠近 OB / 在 FVG / VWAP 相关 position tag

**匹配阈值（偏松）**
- full：sweep+reclaim+结构确认（有 OB/FVG 区更佳）
- partial：上述 required 交集 ≥2
- 甚至仅有 sweep 或 reclaim 也可 `matched=True`（confidence=insufficient）

**方向提示**：多偏好 equal_lows 回收；空偏好 equal_highs 回收（若有 liquidity_states）。

**无独立出场** → 继承底层信号结算。

---

### 4.2 `trend_pullback_continuation` · 趋势回调延续
**匹配步骤**
- LTF 趋势与方向一致（up→long / down→short）
- 回踩到 OB/FVG/VWAP
- 延续：BOS 事件 **或** 量价推进

**匹配阈值**
- aligned + pullback + continuation → partial（仍缺 HTF：1h/4h 结构、full_range_box）
- 仅 aligned(+pullback) 也可 matched（insufficient）

**无独立出场** → 继承底层。  
**相对不差**：BTC 85 笔合计约 **-4.76u**（仍略负）。

---

### 4.3 `range_mean_reversion` · 震荡区间
**区间代理**
- `structure.trend == transition`，或
- 近摆动波幅 / close ≤ 4%

**其它步骤**
- 靠近 session 高低带（1.5% 内）
- 边界 sweep/reclaim
- VWAP confirm / 量价 confirm

**匹配**：有 bound_sweep_or_reclaim 且步骤≥2；或有 range_proxy 且步骤≥2。  
**缺**：完整 range box。  
**无独立出场** → 继承底层。

## 5. 6 个月结果快照（便于优化目标函数）

口径：每笔保证金 1u；结构/研究用 build_settle_plan；回踩用成本防守引擎。

| 标的 | 结构总计(u) | 回踩总计(u) | 流动性反转(u) | 震荡区间(u) | 趋势回调(u) |
|---|---:|---:|---:|---:|---:|
| BTC | -43.52 | -16.07 | -42.26 | -41.61 | -4.76 |
| ETH | -69.86 | -32.42 | -68.23 | -64.42 | -27.49 |
| DOGE | -9.32 | -2.66 | -9.32 | -4.88 | -1.37 |
| UNI | -15.47 | -2.86 | -14.89 | -9.88 | -4.70 |

**可观测弱点**
1. 胜率≈50% 但 payoff&lt;1（均亏 &gt; 均盈）
2. `bottom_secondary_test` 样本占比过大且拖累重
3. 研究策略匹配过松 → 几乎等于全量结构
4. 回踩胜率过低（&lt;30%）
5. 高杠杆放大负期望观感；优化应盯 **1u 期望值 / payoff / 利润因子**，不只盯胜率
